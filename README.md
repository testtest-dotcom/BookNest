# BookNest - лабораторные работы 1-4

Учебный проект по дисциплине «Современные веб-технологии» (W2–W5).

## Запуск

Используйте HTTP-сервер (ES modules не работают корректно при открытии `file://`).

```bash
python -m http.server 8000
```

Откройте http://localhost:8000/ . При наличии Node.js можно использовать `npx serve .`.

## Этапы Git

- `lab-1/markup` — семантические HTML-страницы (без CSS/JS).
- `lab-2/styles` — CSS, темы и адаптивные макеты.
- `lab-3/js-app` — локальный каталог из 40 книг, фильтры, список желаемого.
- `lab-4/api` — Open Library API, debounce, отмена, пагинация.
- `main` — последний этап (содержимое ЛР 4).

Для просмотра конкретной работы `git switch lab-1/markup` (и аналогично для остальных).

## Проверка

1. Проверить все три HTML-страницы через https://validator.w3.org/nu/ (input «Check by text» или URL опубликованного сайта).
2. В Lighthouse проверить Accessibility (≥90), в DevTools ширины 375/768/1440 и обе темы; сохранить реальные скриншоты.
3. На этапе 3 проверить поиск, жанр, доступность, сортировки, список желаемого и сохранение при перезагрузке.
4. На этапе 4: поиск `python`, быстрая смена запроса (Network → canceled), Offline, Slow 4G, пустая выдача, повтор и 404 на странице книги.
5. Создать PR из каждой ветки в GitHub, приложить скриншоты и самопроверку. GitHub Classroom и PR нельзя создать без доступа к вашему аккаунту.

## Ограничения и внешние зависимости

ЛР 4 требует интернет и доступность https://openlibrary.org. Отдельный API может отдавать неполные сведения (например, жанр/рейтинг/доступность); в этом случае поля отображаются как «не указано» и не выдумываются. «Только доступные» для API не выводится из отсутствующего поля: кнопка отключена, если Open Library не вернул сведения. Успешность W3C/Lighthouse, скриншоты и реальная отправка PR не подтверждены автоматически.

Инструкция по загрузке и созданию PR: `docs/GITHUB_STEPS.md`. Для последовательных PR используйте базовые ветки из инструкции, поскольку `main` в готовом архиве содержит итог ЛР 4.
